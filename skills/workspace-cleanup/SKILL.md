# Workspace cleanup

Everything this removes is either regenerated by a build or already on GitHub.
Nothing here touches the remote. The goal is that an idle clone holds the source and
`node_modules`, and nothing else.

## 1. Build output

These are all git-ignored and recreated on demand. The site's build output lives
in `apps/site/`:

| Path | Created by |
| --- | --- |
| `apps/site/dist/`, `apps/site/.output/` | `npm run generate` |
| `apps/site/.nuxt/`, `apps/site/.nitro/`, `apps/site/.cache/` | `npm run dev` / `generate` |
| `apps/site/.data/` | Nuxt Content's local SQLite cache |
| `.wrangler/` (any workspace) | a local `wrangler` run |
| `apps/site/scripts/explainers/out/` | explainer feed renders |

Delete them once you're no longer running the dev server or inspecting a build:

```
npx nuxi cleanup apps/site   # .nuxt, .output, node_modules/.vite, node_modules/.cache
rm -rf apps/site/dist apps/site/.data
find . -name .wrangler -type d -prune -not -path './node_modules/*' -exec rm -rf {} +
```

Leave `node_modules/` in place unless you're about to reinstall anyway.

## 2. Worktrees

```
git fetch --prune
git worktree list
```

A worktree can go once **all** of these hold:

- Its branch's PR is merged or closed (`gh pr list --state all --head <branch>`). PRs
  are squash-merged, so `git branch --merged` doesn't detect them: ask GitHub.
- `git -C <path> status --short` is empty, or you've confirmed the changes are
  disposable.
- It isn't **locked**. A lock means a running agent session still owns it, so leave it
  for that session to clean up.

Then remove it:

```
git worktree remove <path>
```

Run `git worktree prune` for entries whose directory is already gone. A worktree
created from WSL is registered under a `/mnt/<drive>/...` path that Windows git can't
resolve, so it shows as *prunable* even though its directory exists. Remove that
directory by its Windows path, then prune.

## 3. Local branches

Delete a local branch once its PR is merged or closed and no worktree uses it:

```
git branch -D <branch>
```

`-D` is needed because squash merges leave the branch unmerged as far as git can
tell. Check the PR state first, as in step 2.

Never delete `master`, the branch of any remaining worktree, or a branch with
commits that exist nowhere else and no PR (`git log origin/master..<branch>`). Ask
first.

## 4. Keep master current

If `master` isn't checked out anywhere, fast-forward it without switching:

```
git fetch origin master:master
```
